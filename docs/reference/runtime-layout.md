# Runtime Layout（运行时目录结构）

本文记录 SpecLite 安装到目标项目后的 runtime layout、installed projections、ownership 边界和 hook / agent descriptor。它回答“目标项目里会出现哪些 SpecLite 文件，以及谁可以管理它们”。

## Default Layout（默认布局）

默认安装会在目标项目中写入以下路径：

| Path | Ownership | Purpose |
|---|---|---|
| `_speclite/config.toml` | `installer-owned` | 项目共享 runtime config，包含 core / module config、Agent descriptors 和 Hook descriptors。 |
| `_speclite/config.user.toml` | `installer-owned` | 本地用户安装回答，例如 `user_name` 和 `communication_language`。 |
| `_speclite/custom/config.toml` | `human-owned` | 团队级 customization 覆盖。存在时 installer 不覆盖。 |
| `_speclite/custom/config.user.toml` | `human-owned` | 个人 customization 覆盖。存在时 installer 不覆盖。 |
| `_speclite/_config/manifest.yaml` | `installer-owned` | installed manifest 和 runtime path contract。 |
| `_speclite/_config/files-index.json` | `installer-owned` | installed files、hash、ownership、sourceRef 和 artifactKind 索引。 |
| `_speclite/_config/skill-index.json` | `installer-owned` | 已安装 Skill mirror 索引。 |
| `_speclite/_config/help-index.json` | `installer-owned` | module help / menu projection。 |
| `_speclite/_config/phase-coverage.json` | `installer-owned` | SDLC phase coverage projection。 |
| `_speclite/scripts/*` | `installer-owned` | legacy compatibility resolver scripts。默认 Skill activation 使用 `speclite resolve`。 |
| `_speclite/hooks/*` | `installer-owned` | installed hook runners 和 hook metadata。 |
| `.claude/skills/*` | `installer-owned` | Claude Skill mirror projection。 |
| `.agents/skills/*` | `installer-owned` | Agents/Codex Skill mirror projection。 |
| `.claude/settings.json` | `installer-owned` when generated by SpecLite | Claude project hook config。已有文件会触发 conflict，不会被覆盖。 |
| `.codex/hooks.json` | `installer-owned` when generated by SpecLite | Codex project hook config。已有文件会触发 conflict，不会被覆盖。 |
| `_speclite-output/*` | `workflow-owned` | 默认 workflow artifact root。 |

## Config Files（配置文件）

`_speclite/config.toml` 是 installer-managed shared config，需要提交到目标项目仓库。它当前包含：

| Section | Source | Purpose |
|---|---|---|
| `[core]` | Core module config | `project_name`、`document_output_language`、`output_folder` 等共享配置。 |
| `[modules.sdlc]` | SDLC module config | `planning_artifacts`、`implementation_artifacts`、`devops_artifacts`、`project_knowledge` 等路径。 |
| `[agents.<agent-id>]` | `module.yaml` Agent roster | 安装时固化 Agent `module`、`team`、`name`、`title`、`icon` 和 description。 |
| `[hooks.<hook-id>]` | hook runtime descriptor | 安装时固化 hook 来源、保护目标、runner、events、platform configs 和 trust note。 |

`_speclite/config.user.toml` 保存本地用户配置，不应提交。当前主要保存：

- `[core].user_name`
- `[core].communication_language`
- `[modules.sdlc].user_skill_level`

> Note: Installer-managed config 不是长期手工编辑面。需要稳定覆盖时，使用 `_speclite/custom/config.toml` 或 `_speclite/custom/config.user.toml`。

## Customization Files（定制文件）

`_speclite/custom/*.toml` 和 `_speclite/custom/*.user.toml` 是 `human-owned`。SpecLite 可以读取它们解析 customization，但 install、update、repair 和 uninstall 不能把它们当作 installer output 重写。

| Path | Scope | Commit Guidance |
|---|---|---|
| `_speclite/custom/config.toml` | 团队级 | 通常提交。 |
| `_speclite/custom/config.user.toml` | 个人级 | 不应提交。 |
| `_speclite/custom/<skill>.toml` | Skill 团队级覆盖 | 通常提交。 |
| `_speclite/custom/<skill>.user.toml` | Skill 个人级覆盖 | 不应提交。 |

## Hook Descriptors（Hook 描述符）

当前 installed hooks 由 hook registry 统一投影：

| Hook | Runtime Root | Protected Target | Events | Behavior |
|---|---|---|---|---|
| `flow-gate-enforcement` | `_speclite/hooks/flow-gate-enforcement` | `protected_skill = "speclite-dev-story"` | `UserPromptSubmit` | 在执行 `speclite-dev-story` 前检查 story-kickoff Flow Gate 通过证据，必要时阻断。 |
| `canonical-source-change-check` | `_speclite/hooks/canonical-source-change-check` | `protected_surface = "assets/source/speclite"` | `PostToolUse`、`Stop` | 在 canonical source 变更后 warning-only 提醒运行 `speclite-check-canonical-source-change`，永远 exit `0`。 |

每个 hook runtime root 都包含 `runner.mjs` 和 `hook-manifest.json`。`_speclite/config.toml` 的 `[hooks.<hook-id>]` descriptor 会记录 `module`、`source_skill`、保护目标、`runtime_root`、`runner`、`events`、`platform_configs` 和 `trust_note`。

`flow-gate-enforcement` runner 只读取 hook event JSON、installed `_speclite/config.toml` 和 `{implementation_artifacts}/flow-gates/<story-key>-story-kickoff-gate.md` 的 frontmatter metadata。它不生成 Flow Gate report、不修改 Story，也不推进 `sprint-status.yaml`。

`canonical-source-change-check` runner 只读取 git diff / staged diff / untracked files 是否触及 `assets/source/speclite/`。触及时调用 support skill 的只读检查脚本并输出 warning JSON，不返回 `decision: block`，不使用 exit code `2`。

Claude config 生成到 `.claude/settings.json`，包含 `UserPromptSubmit`、`PostToolUse` 和 `Stop`。Codex config 生成到 `.codex/hooks.json`，使用 event-keyed `{"hooks": {"Event": [...]}}` 形态。已有 project hook config 会触发 manual action，installer 不覆盖。

Codex 项目 hooks 需要用户通过 `/hooks review` / `/hooks trust` 之类的本地信任流程后才会生效。SpecLite 文档应把 hooks 描述为 deterministic guardrail，而不是完整 workflow engine。

## IDE Mirrors（IDE 投影）

SpecLite 会把 canonical Skill packages 投影到 selected IDE targets：

| IDE Target | Mirror Path | Notes |
|---|---|---|
| `claude` | `.claude/skills/<skill-id>/` | Claude Skill package mirror。 |
| `agents` | `.agents/skills/<skill-id>/` | Agents/Codex Skill package mirror。 |

当前 official source snapshot 包含 13 个 core package roots 和 48 个 SDLC package roots。默认同时选择 `core` 和 `sdlc` 时，每个 selected IDE target 会获得对应 skill mirrors。

## Artifact Root（产物根目录）

默认 `core.output_folder` 是 `_speclite-output`。SDLC Module 在其下创建：

| Directory | Purpose |
|---|---|
| `_speclite-output/planning-artifacts/` | Brainstorming、Brief、PRD、UX、Architecture、Epics 等规划产物。 |
| `_speclite-output/implementation-artifacts/` | Stories、Flow Gates、Code Reviews、Story Reviews、Retrospectives 等实现产物。 |
| `_speclite-output/devops-artifacts/` | CI/CD、deployment 和 npm release reports。 |

这些 artifact 属于 `workflow-owned`。它们记录真实研发过程，不参与 install/update 覆盖，也不会被 uninstall 自动删除。

## Ownership Summary（所有权摘要）

| Ownership | Examples | Command Behavior |
|---|---|---|
| `installer-owned` | `_speclite/config.toml`、`_speclite/_config/*`、`_speclite/hooks/*`、IDE skill mirrors | installer 可以 update、repair 或 uninstall，但仍要经过 manifest/hash/plan/authorization。 |
| `human-owned` | `_speclite/custom/*.toml`、`_speclite/custom/*.user.toml` | update 跳过，uninstall preserve。 |
| `workflow-owned` | `_speclite-output/*` 或 configured `artifactRoot` 下的产物 | update 跳过，uninstall manual action。 |

详细保护模型见 [`../explanation/file-ownership-model.md`](../explanation/file-ownership-model.md)。
