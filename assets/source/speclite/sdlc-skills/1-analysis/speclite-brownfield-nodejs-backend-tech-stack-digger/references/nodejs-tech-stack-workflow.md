# NodeJS Tech Stack Workflow

## Overview（概述）

本文定义 `speclite-brownfield-nodejs-backend-tech-stack-digger` 的 Node.js 专属执行规则。输出仍遵守通用后端报告契约。

## Inputs（输入）

| 参数 | 必需 | 说明 |
| --- | ---: | --- |
| `{project-root}` | 是 | Node.js 既有项目根目录。 |
| `{output-dir}` | 是 | Markdown 报告输出目录；缺失时必须询问用户。 |
| `{report-name}` | 否 | 默认 `nodejs-backend-tech-stack.md`。 |
| `{package}` | 否 | 指定 workspace package；未提供时自动识别后端 service package。 |

## Evidence Precedence（证据优先级）

1. Lockfile and resolved facts: `package-lock.json`, `npm-shrinkwrap.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lockb`, `npm ls`, `pnpm list`, `yarn list`, `bun pm ls`.
2. Package manifests: root and package `package.json`, `packageManager`, workspaces, `engines`, scripts, dependencies, devDependencies, peerDependencies.
3. Runtime evidence: `.nvmrc`, `.node-version`, Volta fields, Docker image, CI setup, deploy runtime config.
4. Build/runtime config: `tsconfig.json`, SWC / Babel / esbuild config, Nest CLI, Next config, environment templates.
5. Source facts: server bootstrap, routing, controllers, middleware, decorators, DI modules, schema/model files, worker entrypoints.
6. Deployment facts: Dockerfile, Compose, Helm, Kubernetes, Procfile, PM2, systemd, serverless config.
7. Historical docs: candidate only; must be cross-validated by code/config/build facts.

## Package Manager Procedure（包管理器流程）

1. Detect package manager in this order: `packageManager`, lockfile, workspace config, install command in CI.
2. Use executable resolution when available:

```bash
npm ls --all --json
pnpm list --recursive --depth Infinity --json
yarn list --json
bun pm ls --all
```

1. If commands fail because dependencies are not installed, private registry is unavailable, or package manager version differs, record the reason and parse lockfiles.
2. Treat `package.json` semver ranges as declared constraints, not installed versions.
3. For workspaces, resolve versions from the target service package plus root workspace lockfile.

## Conflict Rules（冲突处理）

- Lockfile or executable resolution wins over `package.json` ranges.
- Target workspace package facts win over unrelated workspace packages.
- Runtime version from deploy image or CI wins over local `.nvmrc` when analyzing deployed stack.
- Client dependency does not prove external server version.
- Dev-only dependencies must not be reported as runtime stack unless source or scripts use them in production.

## Output Requirements（输出要求）

Report must include:

1. `Backend Tech Stack（后端技术栈）` with Node.js oriented checklist.
2. `Evidence Summary（证据摘要）` with component, version, evidence, and resolution mode.
3. `Unconfirmed（未确认项）` for missing lockfile, package manager command failures, runtime ambiguity, and server versions.
4. `Verification Commands（核验命令）` listing commands actually run or recommended.
5. `Generated By（生成来源）`: `speclite-brownfield-nodejs-backend-tech-stack-digger`.

## Stop Conditions（停止条件）

- `{output-dir}` is missing and user has not supplied it.
- Target report exists and user has not authorized overwrite, append, or rename.
- No `package.json` or Node.js backend source facts can be found.
- Private registry or missing install state prevents executable resolution; continue only with lockfile/static parsing and explicit uncertainty.
