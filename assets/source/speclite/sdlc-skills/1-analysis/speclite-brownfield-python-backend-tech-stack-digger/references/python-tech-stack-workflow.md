# Python Tech Stack Workflow

## Overview（概述）

本文定义 `speclite-brownfield-python-backend-tech-stack-digger` 的 Python 专属执行规则。输出仍遵守通用后端报告契约。

## Inputs（输入）

| 参数 | 必需 | 说明 |
| --- | ---: | --- |
| `{project-root}` | 是 | Python 既有项目根目录。 |
| `{output-dir}` | 是 | Markdown 报告输出目录；缺失时必须询问用户。 |
| `{report-name}` | 否 | 默认 `python-backend-tech-stack.md`。 |
| `{package}` | 否 | 指定 service package；未提供时自动识别后端 package / app。 |

## Evidence Precedence（证据优先级）

1. Lockfile and resolved facts: `poetry.lock`, `uv.lock`, `Pipfile.lock`, pinned `requirements*.txt`, Conda lock, `pip freeze`, `pipdeptree`, `poetry show`, `uv pip list`, `conda list`.
2. Packaging manifests: `pyproject.toml`, `setup.cfg`, `setup.py`, `requirements.in`, `Pipfile`, `environment.yml`, `tox.ini`, `noxfile.py`.
3. Runtime evidence: `requires-python`, `.python-version`, Docker image, CI setup, Conda environment, toolchain config.
4. Build/runtime config: ASGI/WSGI config, Django settings, env templates, logging config, process manager config.
5. Source facts: `manage.py`, ASGI / WSGI app, routers, views, blueprints, middleware, dependency injection, models, schemas, worker entrypoints.
6. Deployment facts: Dockerfile, Compose, Helm, Kubernetes, Procfile, gunicorn / uvicorn / celery command, serverless config.
7. Historical docs: candidate only; must be cross-validated by code/config/build facts.

## Packaging Procedure（包管理流程）

1. Detect tool in this order: lockfile, `pyproject.toml` build backend, wrapper scripts, CI install command.
2. Use executable resolution when environment is available:

```bash
poetry show --tree
uv pip list
pip freeze
pipdeptree --json-tree
conda list
```

1. If commands fail because virtualenv is missing, interpreter differs, private index is unavailable, or dependencies are not installed, record the reason and parse lockfiles/manifests.
2. Treat `pyproject.toml`, `setup.cfg`, and `setup.py` version ranges as declared constraints, not installed versions.
3. For monorepos, resolve versions from the target service package plus root dependency constraints.

## Conflict Rules（冲突处理）

- Lockfile or executable resolution wins over manifest ranges.
- Target service package facts win over unrelated packages in a monorepo.
- Deploy runtime image wins over local `.python-version` when analyzing deployed stack.
- Client dependency does not prove external server version.
- Dev/test dependencies must not be reported as runtime stack unless production entrypoints use them.

## Output Requirements（输出要求）

Report must include:

1. `Backend Tech Stack（后端技术栈）` with Python oriented checklist.
2. `Evidence Summary（证据摘要）` with component, version, evidence, and resolution mode.
3. `Unconfirmed（未确认项）` for missing lockfile, environment command failures, runtime ambiguity, and server versions.
4. `Verification Commands（核验命令）` listing commands actually run or recommended.
5. `Generated By（生成来源）`: `speclite-brownfield-python-backend-tech-stack-digger`.

## Stop Conditions（停止条件）

- `{output-dir}` is missing and user has not supplied it.
- Target report exists and user has not authorized overwrite, append, or rename.
- No Python packaging file or backend source facts can be found.
- Private index or missing virtualenv prevents executable resolution; continue only with lockfile/static parsing and explicit uncertainty.
