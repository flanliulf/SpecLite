[Overview]
    This Skill reviews PRD, UX, Architecture, and Epics / Stories for implementation-readiness consistency. It embeds a built-in grilling protocol (derived from the grill-with-docs method; it does not depend on the `speclite-grill-with-docs` Skill): challenge each branch of the design against the existing domain model and documented decisions, answer evidence-resolvable questions first, then raise one recommended decision and patch, verify, and record it.

[Core Capabilities]
    - **UX input path governance**: use Planning root evidence to prefer `{planning_artifacts}/ux/ux-design-specification.md`, read the exact legacy fallback only when canonical is absent, and record `resolvedRoot`, `resolutionMode`, `actualConsumedPath`, and the no-migration boundary.
    - **Target document discovery**: Locates canonical PRD, UX, Architecture, Epics / Stories, shared UX / route contracts, readiness / review / spec / prototype gate reports, and archive artifacts.
    - **Embedded grill protocol**: Applies terminology sharpening, design-tree probing, concrete scenario stress tests, code/document cross-checking, single-question recommendations, and inline documentation updates.
    - **Strict-serial rounds**: Uses 50 grill questions per round by default, records each `round-N` separately, and forbids parallel handling of multiple questions.
    - **Dimension coverage matrix**: Covers source of truth, traceability, terminology, UX contract, API schema, state lifecycle, evidence gate, runtime ownership, security / privacy, QA fixture, and implementation handoff.
    - **Issue taxonomy and repair**: Classifies findings as missing anchor, orphan reference, overclaim, terminology drift, gate evidence gap, snapshot freshness gap, handoff gap, and similar classes with targeted fixes.
    - **Prompt orchestration**: Defines goal prompts, round prompts, single-question prompts, repair prompts, verification prompts, and final handoff prompts.
    - **Record and output rules**: Defines locations, fields, and checks for `PLAN.md`, `EXPERIMENTS.md`, `EXPERIMENT_NOTES.md`, and `summary.md`.
    - **Exit gates**: Distinguishes `COMPLETE`, `CONTINUE`, and `BLOCKED` so the process does not loop forever or claim completion with blockers open.

[Workflow]
    1. Read `references/workflow.md` first to confirm input documents, output directory, round number, question count, and exit conditions.
    2. Read `references/prompt-library.md` when organizing a goal or subtask prompt.
    3. Read `references/record-output-spec.md` when creating or validating record files.
    4. Read `references/review-dimensions.md` when selecting review dimensions or classifying issues.
    5. Read `references/testing-scenarios.md` when validating this Skill trigger behavior or execution quality.
    6. Every grill question must complete: evidence check -> question and recommended decision -> targeted patch -> verification -> record. If the user explicitly requests read-only work, output findings only and do not modify files.

[Notes]
    - By default, modify only planning artifacts, IR grill records, and documents explicitly requested by the user; do not modify product source code.
    - If the user authorizes execution or asks to apply recommendations, the recommended decision may be applied directly. If the question depends on a real product decision, legal/compliance commitment, or conflicting canonical sources that evidence cannot resolve, HALT and ask the user.
    - Each round defaults to 50 questions. Unless the user sets a different count, do not merge multiple questions into one experiment and do not replace per-question verification with a batch summary.
    - This Skill can work with `speclite-implementation-readiness-check`, `speclite-review-adversarial-general`, `speclite-review-edge-case-hunter`, `speclite-flow-gate`, and `speclite-index-docs`; the core grill protocol is governed by this Skill's embedded rules.
    - Generated output documents must end with `This document was generated by speclite-implementation-readiness-grill-consistency-reviewer Skill`.
