# Speclite Brownfield NodeJS Backend Tech Stack Digger

[Overview]
    Speclite Brownfield NodeJS Backend Tech Stack Digger is a 1-analysis workflow for Node.js backend stack discovery. It follows the generic `speclite-brownfield-backend-tech-stack-digger` report contract while specializing in npm / pnpm / Yarn / Bun, lockfiles, Node runtime evidence, TypeScript, Express, NestJS, Fastify, Koa, ORMs, queues, cache, security, and testing facts.

[Core Capabilities]
    - **Node project discovery**: Identifies package workspaces, monorepos, service packages, backend entrypoints, `scripts.start`, Docker, and Procfile commands.
    - **Package manager and version resolution**: Prefers `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `bun.lockb`, and package manager metadata for actual dependency versions.
    - **Runtime detection**: Extracts Node.js version evidence from `engines.node`, `.nvmrc`, `.node-version`, Volta, Docker images, and CI setup.
    - **Framework detection**: Identifies Express, NestJS, Fastify, Koa, Hapi, Apollo Server, Next.js API routes, and backend entrypoints.
    - **Data and middleware analysis**: Detects Prisma, TypeORM, Sequelize, Mongoose, Knex, Drizzle, Redis clients, BullMQ, Kafka, RabbitMQ, object storage, and HTTP clients.
    - **Security and engineering stack classification**: Detects Passport, JWT / jose, OAuth/OIDC, validation, logging, metrics, OpenAPI, Jest, Vitest, and Supertest facts.
    - **Evidence-linked Markdown output**: Generates a numbered checklist, evidence summary, unresolved items, and verification commands with `assets/nodejs-tech-stack-report-template.md`.

[Workflow]
    This Skill uses a Node.js specific sequential analysis workflow. Package manager matrices, framework detectors, and version rules are in `references/nodejs-tech-stack-workflow.md`.

    1. Parse user input and confirm `{project-root}`, `{output-dir}`, and `{report-name}`. If `{output-dir}` is missing, ask first.
    2. Read the generic report contract: output must remain compatible with `speclite-brownfield-backend-tech-stack-digger` sections and evidence rules.
    3. Scan Node.js build entrypoints: `package.json`, workspace config, lockfiles, runtime version files, Dockerfile, CI pipeline, and service package.
    4. Prefer executable resolution: run `npm ls`, `pnpm list`, `yarn list`, or `bun pm ls` depending on the package manager. On failure, record the reason and fall back to lockfile / manifest parsing.
    5. Read runtime config and source entrypoints to fill framework, server, database, Redis, MQ, scheduler, storage, auth, API docs, observability, and test facts.
    6. Merge facts and tag sources. `package.json` semver ranges are not actual installed versions; external server versions require deploy evidence.
    7. Write `{output-dir}/{report-name}`, defaulting to `nodejs-backend-tech-stack.md`; final response includes path, key versions, and unresolved items.

[Notes]
    - This Skill only analyzes Node.js backend stacks; Java / Spring Boot, Python, Go, .NET, and other ecosystems should use their own specific Skills or the generic backend contract.
    - Lockfiles are the highest-priority source for actual dependency versions; `package.json` ranges are declaration facts only.
    - Node.js runtime version must come from `engines`, runtime files, Docker image, Volta, CI, or user evidence, not dependency inference.
    - Next.js counts as a backend framework only when API routes, route handlers, server actions, or custom server evidence exists.
    - Redis Server, PostgreSQL Server, Kafka Broker, S3 / MinIO Server, and other external server versions cannot be inferred from Node client versions.
    - Reports must include `Generated By`: `speclite-brownfield-nodejs-backend-tech-stack-digger`.
