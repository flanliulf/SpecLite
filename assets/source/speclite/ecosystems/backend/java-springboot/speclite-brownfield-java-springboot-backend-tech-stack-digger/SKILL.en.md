[Overview]
    Speclite Brownfield Java SpringBoot Backend Tech Stack Digger is a 1-analysis workflow for Java and Spring Boot backend stack discovery. It follows the generic `speclite-brownfield-backend-tech-stack-digger` report contract while specializing in Maven / Gradle, BOMs, Spring Boot, Spring Cloud, Servlet containers, JDBC, ORM, schedulers, cache, and security facts.

[Core Capabilities]
    - **Java module discovery**: Identifies Maven / Gradle roots, modules, parent POMs, BOMs, bootstrap modules, service modules, and packaging mode.
    - **Dependency version resolution**: Prefers Maven effective-POM, dependency tree, Gradle dependencies, lock files, and dependencyManagement for actual versions.
    - **Spring ecosystem detection**: Extracts Spring Boot, Spring Framework, Spring Cloud, Spring Cloud Alibaba, Spring Security, Actuator, OpenFeign, Gateway, and related versions.
    - **Runtime and container detection**: Confirms Java / JDK version, compiler target, toolchain, Docker runtime image, embedded Tomcat / Jetty / Undertow, or external container facts.
    - **Data access analysis**: Detects JDBC drivers, datasources, connection pools, MyBatis, MyBatis-Plus, JPA / Hibernate, Flyway / Liquibase, and DDL evidence.
    - **Middleware and engineering stack classification**: Detects MQ, Redis clients, local cache, schedulers, object storage, HTTP clients, serialization, mapping, API docs, tests, and observability.
    - **Evidence-linked Markdown output**: Generates a numbered checklist, evidence summary, unresolved items, and verification commands with `assets/java-springboot-tech-stack-report-template.md`.

[Workflow]
    This Skill uses a Java / Spring Boot specific sequential analysis workflow. Detailed version rules, category matrix, and command strategy are in `references/java-springboot-tech-stack-workflow.md`.

    1. Parse user input and confirm `{project-root}`, `{output-dir}`, and `{report-name}`. If `{output-dir}` is missing, ask first.
    2. Read the generic report contract: output must remain compatible with `speclite-brownfield-backend-tech-stack-digger` sections and evidence rules.
    3. Scan Java build entrypoints: root `pom.xml` / `build.gradle`, module POMs, parent POMs, BOMs, `settings.gradle`, `gradle.lockfile`, `maven-wrapper.properties`, and `gradle-wrapper.properties`.
    4. Prefer executable resolution: run Maven `help:effective-pom` and `dependency:tree`; for Gradle run `dependencies`. On failure, record the reason and fall back to static parsing.
    5. Read runtime config and source entrypoints to fill Spring Boot, Servlet container, datasource, Redis, MQ, scheduler, storage, security, API docs, observability, and test facts.
    6. Merge facts and tag sources. Client versions must not infer server versions; external server versions require deploy evidence.
    7. Write `{output-dir}/{report-name}`, defaulting to `java-springboot-backend-tech-stack.md`; final response includes path, key versions, and unresolved items.

[Notes]
    - This Skill only analyzes Java / Spring Boot backend stacks; Node.js, Python, Go, .NET, and other ecosystems should use their own specific Skills or the generic backend contract.
    - Versions from parent POMs, BOMs, internal frameworks, dependencyManagement, or Gradle platforms must be labeled with the exact source.
    - Spring Boot version is not the same as `spring-boot-maven-plugin` version; prefer `spring-boot-dependencies.version` or resolved dependency facts.
    - Tomcat / Jetty / Undertow patch versions must come from effective dependencies, not Spring Boot major-version inference.
    - PostgreSQL Server, Redis Server, RocketMQ Server, MinIO Server, and other external server versions cannot be inferred from Java client versions.
    - Reports must include `Generated By`: `speclite-brownfield-java-springboot-backend-tech-stack-digger`.
