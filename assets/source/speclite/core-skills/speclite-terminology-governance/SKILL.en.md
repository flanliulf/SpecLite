[Overview]
    Extract, explain, and normalize project terminology from PRDs, UX documents, Architecture, SPECs, Epics, Stories, and technical solution documents. Outputs are separated into Terminology Inventory, Glossary Projection, and Domain Candidate Handoff. A public Glossary is always a derived reference: it neither overrides an owning artifact nor proves that a capability is implemented.

[Core Capabilities]
    - **Epic Glossary**: Read each Epic section and generate a separately numbered terminology document with Chinese direct names and human-readable definitions.
    - **Story Expansion**: Optionally scan Story acceptance criteria, states, failures, and data contracts, adding only terms that carry implementation-boundary meaning.
    - **Cross-Artifact Governance**: Normalize case, plurality, and hyphenation aliases while preserving provenance and reporting polysemy or cross-artifact conflicts.
    - **Chinese Term Inclusion**: Include project-specific Chinese compounds that affect rules or are prone to drift, without turning ordinary prose into terminology.
    - **Human-Readable Projection**: Generate Epic pages with `Term | 中文直译 | Definition`, a shared inventory, and a glossary index.
    - **Domain Candidate Handoff**: Select candidate business rules, states, events, commands, policies, Entities, and Value Objects for confirmation by `speclite-domain-modeling`.
    - **Deterministic Validation**: Use `scripts/validate_glossary.py` to check numbering, titles, tables, Chinese names, duplicates, conflict states, and index links.

[Workflow]
    Read `references/terminology-governance-workflow.md` for the complete workflow.

    Step 1: Confirm `source_documents`, mode, `glossary_root`, and write authorization. If no output is specified, inspect the project documentation policy, then fall back to `{project_knowledge}/glossary/`, where `{project_knowledge}` is the `resolvedRoot` returned by `speclite resolve artifact-roots --project-root {project-root}`.

    Step 2: Establish provenance by source responsibility, extract candidates section by section, then classify, name, define, and normalize them using `references/term-taxonomy-and-promotion.md`.

    Step 3: Generate or update the Terminology Inventory before projecting Epic Glossaries. Public index navigation is a separate write surface; list touched files before changing it.

    Step 4: Run `python3 scripts/validate_glossary.py <glossary-root> --require-index --format json`, repair only reported locations, and repeat for no more than three rounds. Stop and report if Errors remain.

    Step 5: Generate `domain-candidates.md` only when domain abstraction is requested. Do not modify `CONTEXT.md` or ADRs without human confirmation.

    - Epics and Stories are Contract / Guidance Anchors; code, tests, and runtime results are Functional / Evidence Anchors. Use the `Contract -> Functional -> Evidence` order to separate intent from current fact.
    - A fixed Story path is a hard gate only when an owning SPEC requires it. Otherwise accept a resolved root or an equivalent implementation policy backed by tests, fixtures, snapshots, or command evidence.
    - This Skill does not advance Epic or Story status, and it does not produce or consume a state-transition `speclite-flow-gate` report. It must not rewrite planned, approved, or accepted as implemented, verified, or released.
