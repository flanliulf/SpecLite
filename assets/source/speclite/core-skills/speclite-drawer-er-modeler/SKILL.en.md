# Drawer ER Modeler

[Overview]
    Convert requirements, planning artifacts, domain materials, or schemas into reviewable ER models and technical diagrams. The Skill name is renderer-neutral; Mermaid `erDiagram` is the current default internal implementation. Never present inference as fact or a design diagram as implementation evidence.

[Core Capabilities]
    - **Field inference gate**: Separate explicit fields, structurally implied candidates, and conventional guesses; emit only a minimum credible model when evidence is sparse.
    - **Layered data design**: Select conceptual, logical, or physical scope; add SQL types, indexes, and constraints only when supported.
    - **Change-object classification**: Classify objects as `existing`, `new`, `modified`, or `unresolved` from explicit evidence.
    - **Deterministic visual semantics**: Apply fixed colors and line styles with a legend; never select colors ad hoc.
    - **Diagram syntax generation**: Generate valid code for the selected renderer; Mermaid output separates keys from comments and formats concise relationship labels as `Chinese(English)`.
    - **Multiplicity narration**: After the diagram, state each `1 : 0..N`-style multiplicity and explain optional/mandatory constraints in both directions.
    - **Integrity and performance rationale**: Explain constraints, indexes, hot queries, and normalization trade-offs without inventing vendor behavior.

[Conventions]
    - Use uppercase `SNAKE_CASE` identifiers, lowercase `snake_case` fields, and `Chinese Name（ENGLISH_IDENTIFIER）` display aliases.
    - Mermaid attributes use `type name [key] ["comment"]`; `PK`, `FK`, and `UK` are keys.
    - Use Crow's Foot cardinalities and double-quoted `Chinese(English)` verbs or verb phrases for Mermaid relationship labels, for example `"包含(contains)"`.
    - Resolve M:N relationships into associative entities in physical models; conceptual models may retain M:N.
    - Follow a confirmed SQL dialect. Otherwise use generic types or omit unreliable vendor details.
    - Read `references/er-drawing-rules.md` completely before execution.

[Workflow]
    1. Confirm scope, audience, dialect, level, renderer, and output location; HALT on material gaps.
    2. Record explicit objects/fields, structural candidates, conventional guesses, and unresolved questions.
    3. Apply the field sufficiency gate; downgrade to conceptual or minimum logical output instead of filling common fields.
    4. Classify each object from explicit wording and authorized schema/code evidence; never infer change status from its name.
    5. Design relationships and minimum fields, then apply fixed colors, a legend, bilingual aliases, and renderer syntax.
    6. After the diagram, generate a multiplicity summary and two directional statements for every relationship; then check consistency with the diagram and evidence.

[Output Contract]
    Output level and scope, renderer, field-sufficiency result, change classification, assumptions/questions, diagram code, relationship multiplicity explanations, rationale, and constraint/index recommendations. Return a minimum credible diagram or gaps instead of fabricating a complete model.
