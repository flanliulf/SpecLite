# Separate Canonical Skill Packages From Adapter Artifacts（区分规范 Skill 包与适配器产物）

SpecLite 将 canonical skill package 视为跨 IDE 严格一致的统一标准，IDE adapter 不得改写 `SKILL.md`、`CHANGELOG.md`、references、assets、scripts、`config.toml.example`、`customize.toml` 或 customization lookup key。`CHANGELOG.md` 与 `config.toml.example` 都属于 skill 定义包的一部分，因为安装后的 skill 在目标项目和 IDE 中应保持固化，直到下一次人为 update/install；human-owned 覆盖只应写入 `_speclite/custom/*.toml`。某个 IDE 需要额外 wrapper、pointer 或 metadata 时，这些文件属于 adapter artifact（适配器产物），manifest 必须分别记录 canonical package hash 与 adapter artifact hash；这样既允许平台加载机制差异，又能让 mirror validation、update protection 和 drift detection 以统一 skill 定义为基准。IDE mirror drift 由 `validate` 报告为 `ide-mirror` 或 `file-integrity` issue，`validate` 不修复；`update` 默认把 installer-owned drift 标记为 conflict，MVP 只有 `speclite update --repair` 或用户确认后才覆盖恢复，不新增顶级 `speclite repair` 命令，`speclite sync` 保持 Post-MVP。`update --repair` 可恢复 IDE mirrors、manifest/index 和 runtime scripts 等 installer-owned files，但不得覆盖 human-owned custom files 或 workflow-owned artifacts；写入前必须生成 repair plan，列出 affected paths、ownership、current hash、expected hash 和 action，交互模式确认后写入，脚本模式需要 `--yes`。
