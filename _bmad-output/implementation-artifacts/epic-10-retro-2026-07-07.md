## Executive Summary（执行摘要）

Epic 10 完成了 `assets/source/speclite/ecosystems/<category>/<id>/` 生态模块治理闭环：官方 source taxonomy 从 only `core` + `sdlc` 扩展到 optional ecosystem modules；install 选择支持 category -> ecosystem id 的两级引导；installed runtime 以 selected modules 作为 truth；fixtures、canonical source check、packaging manifest、public docs 和 maintainer workflow 均同步到 ecosystem 模型。

本 Epic 的主要价值不是新增若干 Skill 目录，而是把“通用 SDLC 方法论”和“技术生态扩展”从 source、module metadata、installer、installed indexes、validation、release gate 到 docs 全链路分离。最终结果是：default install 仍保持 `core` + `sdlc`，selected ecosystem modules 只有在用户选择后进入 IDE mirrors 和 installed-state indexes，未选择 ecosystem modules 保持 source-only。

主要学习是：selected-only projection 的风险面比最初看起来更深。CR 反复发现 false-green 类问题，例如 core-only installed state 绕过 selected-module validation、`files-index` 残留未选 source refs、`skill-index` selected root completeness 被最小合法 root 集绕过。后续所有 source taxonomy 扩展都必须把 executable gate、negative assertions 和 release packaging check 视为同一条 contract，而不是分散在 docs、tests 和 reviewer 记忆中。

## What Worked（有效实践）

- **Story Review before implementation（开发前 Story Review）**: Round 1 在实现前发现 Dependency Gate、Final Publication Gate 和 ownership split 缺口，避免 10.3/10.4/10.6 过早承诺尚未有证据的能力。
- **Minimal proof then matrix generalization（最小证明再矩阵泛化）**: 10.1 只负责 backend 最小 selected-only proof，10.5 承接 full matrix fixture / release / canonical source check，减少职责重叠。
- **Negative assertions as first-class evidence（负向断言作为一等证据）**: selected React/Vue/backend/other、unselected same-category、cross-category absence、core-only installed state 等负向场景把 false green 风险显性化。
- **Release gate dynamic inventory（发布门禁动态清单）**: 10.5 将 packaging assertion 从示例 module 扩展为扫描全部 nested ecosystem modules，避免新增生态后 release check 仍误报通过。
- **Docs gated by completion evidence（文档由完成证据解锁）**: 10.6 要求最终 public docs、catalog、runtime layout 和 release workflow 读取 10.3 / 10.4 / 10.5 completion evidence，避免用户可见文档先于实现事实。

## Problems and Fixes（问题与修复）

- **Two-level install prompt gap（两级安装提示缺口）**: 10.1 首轮 CR 发现 interactive install 仍偏向一次 exact module code prompt。修复后 category prompt、ecosystem id prompt、skip、unknown / empty answer 和 programmatic exact module code selection 均进入闭环。
- **Executable gate gap for `other`（`other` 准入缺少可执行门禁）**: 10.4 首轮 CR 发现 `other/misc`、`other/general`、`other/tools` 主要停留在 docs/guidance 禁止。修复后 runtime metadata validation、canonical checker 和负例测试共同拒绝 banned ids。
- **Selected-state validation bypass（选择状态验证绕过）**: 10.5 首轮 CR 发现 core-only installed state 可绕过 selected-module validation。修复后 `manifest.installedModules` 直接驱动 skill/help/phase/files indexes 的 selected module truth 校验。
- **Packaging assertion too example-based（打包断言过度示例化）**: 10.5 首轮 CR 发现 release gate 只证明部分 ecosystem source files。修复后 packaging check 动态枚举全部 `ecosystems/<category>/<id>/module.yaml` 和 `SKILL.md` package roots。
- **Generated output exclusion gap（生成产物排除缺口）**: 10.5 首轮 CR 发现 release packaging exclusion gate 未覆盖 cache/temp/build output。修复后 `.cache`、`cache`、`tmp`、`temp`、`build` 和 source-local `dist` 类路径进入负向断言。
- **Docs / governance drift（文档与治理漂移）**: 10.6 首轮 CR 发现 skill catalog 与 canonical governance map 对 ecosystem 归属表达不足。修复后 SDLC / ecosystem catalog 归属、ecosystem-only canonical change classification 和 focused docs tests 收口。
- **Index-level false greens（索引层假绿）**: 10.6 后续 CR 发现 `files-index` 和 `skill-index` 仍有 selected-only validation gap。最终通过统一 sourceRef/moduleId 归属校验和 official bundled root completeness gate 关闭。

### Preparation Gates（准备门禁）

1. **Gate Artifact Read（门禁产物读取）**: 启动任何后续 ecosystem / canonical source Story 前，必须读取相关 SR/CR/final verification 记录，不得只依赖 `sprint-status.yaml`。
2. **Selected Truth Gate（选择真相门禁）**: 新增或迁移 package root 时，必须证明 selected module truth 同时约束 `skill-index`、`help-index`、`phase-coverage` 和 `files-index`。
3. **Dynamic Release Gate（动态发布门禁）**: packaging / canonical source check 必须从 source tree 动态枚举 expected ecosystem roots，不能只检查示例 module。
4. **Docs Publication Gate（文档发布门禁）**: public docs、catalog、runtime layout 和 maintainer workflow 更新必须有对应 Story completion evidence 或明确标记未完成能力。
5. **Mixed Worktree Boundary Gate（混合工作区边界门禁）**: 后续 CR / finalizer 必须继续记录排除范围，尤其是 PPT / html-ppt 相关外部 drift，不得顺手纳入无关修改。
