### Challenges（挑战）

- Resolver 依赖的默认 `python3` 多次失败，因为系统 Python 缺少 `tomllib`；多份 Story 记录都显示需要切换到 `python3.12`。
- Reviewer/evaluator 阶段反复遇到 `node_modules` 缺失，导致部分只读复审不能独立重跑 `npm test` / `npm run build`，只能引用 dev/fixer record。
- 多个 CR finding 指向 public JSON contract 容易被临时字段污染，例如 `selectedModules`、`pendingModuleSelection`、`readySummary`、`failedStep`、`changedPaths`。
- 写入安全和路径安全的复杂度高于普通 installer：target symlink、regular file、installed-state index corruption、mirror directory creation、workflow-owned artifact protection 都需要专门测试。
- Source package inventory 曾出现 stale understanding，SR Round 2 evaluator 发现 `sdlc-skills` nested package roots 判断过期，最终通过 Story 1.3 / 1.5 / 1.6 修订关闭。

### Key Lessons（关键经验）

1. Contract anchors 必须先于 command orchestration 扩展，否则 public output 会快速分叉。
2. Installer 的 "no write before confirmation" 不能只靠流程说明，必须用 forbidden path assertions 固化。
3. Existing install detection 不能把路径存在性当作 schema 有效性；触达的 manifest/index 都要读取和校验。
4. Human-readable output 也是产品契约，target summary、manifest unavailable、IDE target visibility 和 redacted path 都要可审计。
5. Safe write 需要覆盖 directory mutation，不只是 file write。
6. Module metadata 与 canonical package roots 必须在 discovery 阶段确定性校验，不能静默跳过缺失 package 或 unknown dependency。
7. Ready summary 不是 generic success 文案；必须由 manifest/index、source descriptor、IDE mirror visibility、installed module evidence 和 runtime paths 支撑。
