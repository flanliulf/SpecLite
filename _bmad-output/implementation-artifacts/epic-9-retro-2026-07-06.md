## Executive Summary（执行摘要）

Epic 9 完成了 installed runtime activation contract 的核心收口：canonical installed skills 默认通过 `speclite resolve` 读取 merged runtime config / customization；legacy Python resolver scripts 被重新定义为 compatibility assets；root-level `data/` 被纳入 self-contained installed skill package surface，并进入 copy、hash、validate、fixture、update/repair 和 packaging gate。

本 Epic 解决的是运行时契约断裂，而不是单个 resolver bug。真实触发点是 installed skill activation 文案、CLI availability、Python fallback、support-side lint、installed mirror、files-index、package hash 和 fixture release gate 之间存在多处边界漂移。Epic 9 的价值在于把这些边界统一为可扫描、可测试、可安装、可验证的 contract。

主要学习是：tracker 只是一种状态视图，不足以表达所有 gate。Epic 9 SR Round 2 专门生成 gate artifact，阻止 Story 9.2 在 Story 9.1 full corpus gate 未通过前启动；后续实现证明该 gate 已解除，但这个过程暴露了外层自动化如果只读 `sprint-status.yaml` 会误判启动条件的风险。

## What Worked（有效实践）

- **Single default resolver（单一默认 resolver）**: `speclite resolve` 成为 installed activation 的唯一默认入口，减少了 Python resolver、source checkout、单文件 config 的并行语义。
- **Negative scan as contract（负向扫描作为契约）**: Story 9.1 / 9.2 不只验证新路径存在，还验证 legacy resolver / single-file config / default compat dependency 不再出现。
- **Gate artifact for exceptional state（异常状态使用 gate artifact）**: Story 9.2 的 `blocked-by-9-1-corpus-gate` 无法安全写入 tracker 枚举时，SR gate artifact 明确了启动优先级。
- **Shared package surface predicate（共享 package surface 谓词）**: Story 9.3 用同一 predicate 驱动 copy、hash、validate，避免 `data/` 只被某一层识别。
- **Fixture from real install（从真实安装刷新 fixture）**: Story 9.3 从真实 `runInstallCommand` 刷新 installed-state，降低手工 hash / tree 编辑误差。

## Problems and Fixes（问题与修复）

- **Python fallback ambiguity（Python fallback 歧义）**: 早期 activation 文案仍可误导 Agent 读取 `_speclite/config.toml` 或调用 Python resolver。修复后默认 path 只允许 `speclite resolve`，Python scripts 只保留 compatibility / troubleshooting 角色。
- **CLI availability blind spot（CLI 可用性盲点）**: AI execution plane 中 bare `speclite` 可能不在 `PATH`。修复后 activation contract 要求显式 CLI availability preflight。
- **Corpus coverage gap（语料覆盖缺口）**: Epic 9 SR Round 1 发现 full corpus scan 未覆盖 `SKILL.en.md` 和 support-side boundary。修复后 corpus coverage 包含 `SKILL*.md`、references、terminal steps、installed mirror 和 support-side negative scan。
- **Tracker / gate mismatch（追踪器与门禁不一致）**: `sprint-status.yaml` 无法表达 Story 9.2 的 blocked state。修复方式是在 SR gate artifact 中记录优先级，并在后续实现中通过 Story 9.1 gate evidence 解除。
- **Data surface omission（data surface 遗漏）**: installed skill packages 没有 root-level `data/`，导致 self-contained workflow 仍依赖 source checkout。Story 9.3 将 `data/**` 纳入 installable surface 并用 tests / fixtures 锁住。
- **Unrelated baseline drift（无关基线漂移）**: Story 9.1 / 9.2 全量测试曾受 unrelated untracked SDLC roots 影响。该问题被记录为 mixed worktree scope risk，没有被强行吸收到本 Story。

## Next Epic Preparation（下一 Epic 准备）

Epic 10 将建立 canonical source ecosystem module governance。Epic 9 对 Epic 10 的直接输入包括：

- installed activation contract 已收口到 `speclite resolve`，ecosystem modules 不能引入 source checkout runtime dependency。
- Python compatibility assets 已分类为 `runtime-compat-script`，ecosystem packaging / fixture gate 不能把 compatibility scripts 当作 default resolver dependency。
- root-level `data/` 已成为 installed skill package surface，ecosystem authoring contract 必须继承 `data/**` copy/hash/validate 规则。
- full corpus gate 与 negative scan 的经验需要扩展到 nested ecosystem modules，尤其是 selected-only projection 和 unselected ecosystem negative assertions。
- mixed worktree baseline drift 需要在 Epic 10 中变成显式 selected module matrix，而不是继续依赖 core+sdlc hardcoded counts。

### Preparation Gates（准备门禁）

1. **Module Taxonomy Gate（模块分类门禁）**: `assets/source/speclite/ecosystems/<category>/<id>/` 必须作为 canonical source taxonomy 被发现和验证。
2. **Selected-only Projection Gate（选择性投影门禁）**: 未选择 ecosystem module 不得进入 IDE mirrors、skill-index、help-index、phase-coverage 或 files-index。
3. **Activation Continuity Gate（激活连续性门禁）**: ecosystem skills 继承 Epic 9 的 `speclite resolve` activation contract，不引入 Python fallback 或 source checkout dependency。
4. **Package Surface Gate（包表面门禁）**: ecosystem skill packages 复用 Story 9.3 的 `data/**` package surface predicate。
5. **Fixture Matrix Gate（Fixture 矩阵门禁）**: core+sdlc baseline 与 selected ecosystem matrix 分开验证，避免数量常量继续漂移。
