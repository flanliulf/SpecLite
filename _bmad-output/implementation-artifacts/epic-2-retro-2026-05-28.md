- Epic 2 初始 Story boundary 高耦合：discovery metadata、IDE mapping、activation target、resolver support 与 artifact metadata 容易跨 Story 提前承诺。

- Story 2.4 仍有 `resolve-parity` fixture 可审阅性 P2 TODO；当前行为测试充足，但 fixture case 尚未完全外置。
- Story 2.5 仍有 `generatedAt` contract P2 TODO；当前 validator 接受 canonical UTC millisecond form，但 Story/SPEC wording 仍需明确是 canonical 形式还是 broader parseable ISO 8601。
- 多个复审记录披露当前 `Agent` 子代理不可用，reviewer 采用主上下文串行 fallback。
- `sprint-status.yaml` 曾出现 Epic 主状态与 Story/retrospective 状态不一致；当前已按 Project Lead 授权同步为 `done`。

### Key Lessons（关键经验）

1. `canonicalSkillId` 必须从 source package root、installed target path、activation target、customization lookup key 到 `sourceSkill` metadata 一路保持一致。
2. `module-help.csv` 是 help/menu/phase metadata source，不是完整 canonical package discovery source。
3. Phase coverage 是阶段发现矩阵；它必须能区分“已安装但未暴露到 phase coverage”和“缺失 installed skill entry”。
4. Installed skill 读取配置和 customization 必须通过 `speclite resolve` runtime command，不能回退到 legacy Python resolver 或 source checkout。
5. Workflow artifact contract 的 root containment、POSIX-style public path 与 metadata value domain 要有唯一真源。
6. P2 TODO 需要明确来源和处理时机；不能把 non-blocking TODO 混回当前 Story fixer scope。
