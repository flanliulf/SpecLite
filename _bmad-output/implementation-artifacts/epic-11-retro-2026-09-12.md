## Executive Summary（执行摘要）

Epic 11 建立了 SpecLite 的阶段对齐 workflow artifact 体系：七类 artifact roots 由 `SPEC 09` 唯一拥有并通过 `src/config/artifact-root-resolver.ts` 可执行解析；fresh install 把 roots 投影到 config、目录、manifest/index 与 Ready Summary；existing install 保持 explicit-config 权威、`legacy-compatible` fallback 与 no-silent-migration 诊断；Analysis / Planning / Solutioning / UX / PRD validation report / Implementation Readiness / Code Review 七类产物各自获得唯一约定位置与 discovery 规则；最后以只读 grill 引用清单完成人工确认闭环。

本 Epic 的核心价值不是"多了几个目录"，而是把 artifact 路径从分散在 installer、manifest、validator、Skill prose 与 tests 中的隐式约定，收敛为同一 resolved model 的多个投影（`resolvedRoot` / `resolutionMode` / stable issue ID / `speclite resolve *` 命令族）。Epic completion gate `PASS`，fresh 验证 727 passed / 0 failed，docs、packaging、canonical strict check 全部通过。

主要学习有三条。其一，"测试全绿 ≠ contract 闭环"：十个 Story 首轮 CR 无一例外用定向复现推翻绿色 suite，fail-closed 缺口是最高频根因。其二，Story 11.9 的首版实现在缺乏威胁模型边界的情况下被三层对抗式审查推向 36 轮仍未收敛，最终依靠 Correct Course 三项裁决重做后 3 轮收敛——任何 resolver / validation 类 Story 必须在 AC 中显式给出 in-scope / out-of-scope 威胁模型。其三，外部 `speclite-drawer-er-modeler` 混入工作树导致 fixed-count 断言漂移，四个 Story 的 completion gate 只能 `PASS_EQUIVALENT`，说明 Epic 10 的"动态枚举"行动项只做到了 manifest 层，未落到测试断言层。

## Problems and Fixes（问题与修复）

- **Fail-open on secondary call surfaces（第二调用面的 fail-open）**: 11.2 ReadyCheck 在 manifest 缺失 `artifactRoots[]` 时仍 `ok=true`；11.3 `status` 在 config 解析失败时静默回退且 `exitCode=0`；11.8 resolver `ok=false` 被 legacy fallback 吞掉；11.9 `checkBoundary` 未覆盖 ELOOP / ENOTDIR / EACCES。均以 stable issue + zero-mutation 断言关闭，沉淀为 `CR-API-35 / 37 / 39 / 41`、`CR-SEC-20`。
- **Symlink / path boundary spread across five rounds（symlink 边界跨五轮补齐）**: 11.1 抽取 helper → 11.3 ownership overlap → 11.4 R4–R6 readability probe → 11.5 R1 / R2 / R6 / R7 declared shard 与 lexical candidate → 11.9 R1 先枚举后检测。最终形态为 lexical lstat + realpath containment + dereferenced regular-file + `open("r")` probe。
- **Executable helper vs installed prose split（可执行 helper 与已安装 prose 分裂）**: 11.4 R5、11.6 R4、11.9 R1-F3 均发现 TS helper 只被 tests 引用而 installed Skill Markdown 仍走旧逻辑。修复方式分别为 Markdown token contract scan、Skill-private script 投影、runner 六个调用串携带 `crDir`；沉淀为 `CR-DOC-05`。
- **Story 11.9 first implementation blow-up（Story 11.9 首版失控）**: AC9 把 current round / unfinished run 判定交给 resolver 且无威胁模型，1.0 / 1.1 演变为 1791 行认证与审批重放引擎，违反 AC12；main 24 轮 + evidence-v2 6 轮（含三次 STOP_LOSS 例外与一次风险接受）+ directory-routing 2 轮仍未收敛。Correct Course 决策 A（威胁模型）/ B（实现位置）/ C（历史归档）后从 `ff7528d` 重做，3 轮收敛。
- **External drawer drift（外部 drawer 漂移）**: 11.4 R2 起 `speclite-drawer-er-modeler` 混入工作树，canonical count 18 → 19 / 68 → 69，full suite 固定 12 failures，11.5–11.8 completion gate 只能 `PASS_EQUIVALENT`；每轮 CR 重复隔离声明。11.9 restart 重生成 fixture 后消失。
- **Test-oracle fail-open（测试预言机 fail-open）**: 11.7 R3–R7 五轮全部是 focused test 自身逻辑反转、config 同义 key、aliased import 等漏网；11.8 R2–R3 control-plane 与 fixture 同源、walker 隐式 exclusion；11.10 validator 只算计数未校验字段自洽。沉淀为 `CR-TEST-08 / 09`。
- **Process incidents（流程事故）**: agent 无响应（11.3 R3 reviewer、11.4 dev、11.4 fixer）、evaluator 越权落盘修复（11.3）、fixer 越权改编排日志（11.4）、并发 invalid provenance（11.4 R3）、11.9 出现"先切 `review` 再补 completion gate"顺序纠正、11.10 CR 首启被 session 中断。恢复方式为 fresh Fixer recovery record 与 Session Reconciliation，但"串行降级"在 11.1–11.3 被接受而在 11.4 R1 被判作废，标准不一致。
- **Verification side effects（验证副作用）**: `npm run build` / `npm test` 改写 `release/packaging-manifest.json` 的 `packageHash`（11.1）；build 与 packaging 并行造成 `dist` 竞态（11.3）；沙箱内 `npm pack` 失败会让 packaging writer 删除 manifest（11.9）；后期 reviewer / fixer 被禁止运行 build / full，closeout 只能引用历史 green。

## Next Epic Preparation（下一 Epic 准备）

当前规划文档与 `sprint-status.yaml` 未定义 Epic 12。Epic completion gate 已列出十项可被后续 Epic 依赖的实现锚点。本节不绑定具体下一 Epic，而是面向任何后续 resolver / validation / canonical Skill 变更类工作。

### Preparation Gates（准备门禁）

1. **Threat Model Gate（威胁模型门禁）**: 任何引入 resolver、validator 或 discovery 的 Story，AC 必须显式给出 in-scope / out-of-scope 威胁模型；CR 对 out-of-scope finding 按契约 `dismiss`。
2. **Installed Binding Gate（已安装绑定门禁）**: 新增 TS helper 或 Skill-private script 时，必须同时证明 installed Skill Markdown 存在可定位的调用点（`CR-DOC-05`），仅 tests 引用不计入完成。
3. **Dynamic Count Gate（动态计数门禁）**: 涉及 canonical Skill 数量的断言必须从 source truth 派生，不得硬编码 `core=N / total=M`。
4. **Gate Precedence Gate（门禁优先级门禁）**: Story 状态切换到 `review` / `done` 前必须存在对应 completion gate 与 finalizer report；tracker 不得先于 gate 更新。
5. **STOP_LOSS Gate（止损门禁）**: CR 达到 STOP_LOSS 阈值时不批例外、不做风险接受，而是回到 Story 边界重新裁决或触发 Correct Course。
6. **Mixed Worktree Boundary Gate（混合工作区边界门禁）**: 继续在每个 completion gate 记录排除范围；fixture 与 packaging manifest 必须按提交树而非脏工作树生成。
