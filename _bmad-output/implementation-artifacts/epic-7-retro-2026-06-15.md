### What Worked（有效实践）

- 严格按 Story scoped `PLAN.md`、`EXPERIMENTS.md`、`EXPERIMENT_NOTES.md` 记录推进，使每轮 CR 的输入、判断和修复范围可追溯。

### Problems and Fixes（问题与修复）

- **Partial Install Risk（部分安装风险）**: Story 7-1 初版在 existing hook config conflict 前已产生部分写入。修复后，hook config conflict preflight 位于任何 install write 之前，冲突返回空 `changedPaths`。
- **Directory Removal Safety（目录删除安全）**: Story 7-2 初版 `uninstall` 对 installer-owned 非空目录使用非 recursive removal。修复后，installer-owned directory removal 与 focused tests 闭环。
- **Contract-First Error Handling（契约优先错误处理）**: Story 7-4 初版 malformed workflow artifact frontmatter 会抛 `YAMLParseError` 并泄露本地绝对路径。修复后，该路径进入稳定 `ValidationIssue` / `CommandResult`，并覆盖 redaction regression。
- **Source Root Boundary（Source Root 边界）**: Story 7-5 初版 `init` / `list` 从 target `process.cwd()` 查找 bundled source metadata。修复后，命令不再把 target project cwd 当作 canonical source root。

## Next Epic Preparation（下一 Epic 准备）

Epic 8 的规划文件将范围限定为 CLI outcome-oriented human output，并明确排除 Post-MVP 新命令：`doctor`、`sync`、`uninstall`、`init`、`list`。因此，Epic 7 的输出经验可以影响 shared output vocabulary 和 CR discipline，但不应默认扩大 Epic 8 的实现范围。

### Scope Boundary（范围边界）

- Epic 8 可以复用 Epic 7 对 `CommandResult`、human output renderer、redaction 与 focused test 的经验。
- Epic 8 不应默认处理 `TODO-010`，因为它属于 Flow Gate hook runner damaged-state resilience。
- Epic 8 不应默认处理 `TODO-011`，除非 scope 明确纳入 Post-MVP `sync` / `uninstall` human output。
- 如果 stakeholder 希望 Epic 8 同时覆盖 Post-MVP 新命令，需要先更新 Epic 8 scope 与对应 Story AC，不应在实现时隐式扩大范围。

### Preparation Gates（准备门禁）

1. **Contract Gate（契约门禁）**: Story 8-1 开始时先确认 JSON contract 不随 human output 改造漂移。
2. **Scope Gate（范围门禁）**: 每个 Epic 8 Story 明确列出覆盖命令和排除命令，避免把 Epic 7 新命令误纳入。
3. **Backlog Gate（Backlog 门禁）**: 在触及 `src/diagnostics/output.ts`、Flow Gate runner 或 release fixture 相关文件时，先检查 `TODO-009`、`TODO-010`、`TODO-011`。
4. **Renderer Gate（Renderer 门禁）**: human output 改造必须先定义 outcome vocabulary、next action taxonomy 和 localized message ownership，再进入实现。
