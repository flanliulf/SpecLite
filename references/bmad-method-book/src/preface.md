# 前言：重新定义人机协作

这不是一本 API 文档，也不是使用手册。

这是一次对 **BMAD-METHOD**（Build More Architect Dreams，筑梦架构）的架构剖析——一个试图重新定义 AI 辅助开发范式的开源框架。我们将从第一性原理出发，分析它的设计选择、架构决策和哲学立场。

## 这本书要做什么

当大多数 AI 开发工具承诺"10 倍速度提升"时，BMAD-METHOD 选择了一条不同的路：**人类增强而非替代**（Human Amplification, Not Replacement）。

这本书试图回答三个核心问题：

1. **为什么**这个框架选择了当前的架构？
2. **什么**设计决策让它区别于其他 AI 开发工具？
3. **如何**将这些设计模式应用到你自己的项目中？

我们不会回避项目的局限和权衡。相反，我们会深入分析每个设计选择的代价——因为诚实的技术评价比营销话术更有价值。

## 核心问题

2025 年，AI 辅助开发已经从概念验证走向生产实践。但一个根本问题仍未解决：

> **如何让 AI 成为真正的协作者，而不是一个会犯错的自动化工具？**

BMAD-METHOD 的答案是：通过结构化工作流、具名智能体、对抗式审查和四层配置系统，建立一套"引导式协作"机制——AI 不是替你思考，而是激发你的最佳思维。

这个答案是否正确？它的代价是什么？有没有更好的替代方案？这些是本书要探讨的问题。

## 关于本书的结构

全书分为八个部分，每个部分聚焦一个核心维度：

- **第一部分**：定义问题——AI 辅助开发的真实挑战
- **第二部分**：核心架构——Skill-first、具名智能体、四层配置
- **第三部分**：数据管道——为什么选择 CSV、文件系统、Git
- **第四部分**：质量保障——对抗式审查的三层架构
- **第五部分**：工作流设计——规模自适应、引导式协作
- **第六部分**：扩展与集成——模块生态、跨平台适配
- **第七部分**：性能与权衡——三大瓶颈、拒绝量化基准的原因
- **第八部分**：设计原则——提炼的五大原则和架构模式

每一章遵循统一结构：**问题 → 约束 → 决策（含源码）→ 证据 → 代价**。

## 数字与证据
