# 第十六章：引导式协作 vs 自动化

> "AI 不应该替你做决定，而应该帮你做更好的决定"
>
> — BMAD-METHOD 设计哲学

---

## 一个关键的选择

当 AI 能力越来越强，开发者面临一个选择：

**选择 A：完全自动化**
```
用户："做一个电商网站。"
AI：[10 分钟后] "完成！"
```

**选择 B：引导式协作**
```
用户："做一个电商网站。"
AI："让我们先理解需求。
     - 目标用户是？
     - 商品类型？
     - 是否需要支付？
     - ..."
```

**大多数 AI 工具的选择**：选择 A（炫酷 demo）

**BMAD-METHOD 的选择**：选择 B（务实生产）

为什么？

## 问题定义：自动化的陷阱

### 陷阱 1：黑盒决策

**场景**：
```
用户："做一个电商网站。"
AI：[自动选择 Shopify 风格 + Stripe 支付 + Next.js]
用户：[3 个月后] "为什么用 Shopify 风格？我们是 B2B。"
AI：[默认假设是 B2C]
```

**问题**：
- AI 替用户做了决策
- 用户不知道为什么
- 决策可能不符合实际需求

### 陷阱 2：上下文丢失

**场景**：
```
用户："做一个 CRM。"
AI：[创建标准 CRM]
用户："我们是医疗行业，需要符合 HIPAA。"
AI：[需要重做]
```

**问题**：
- AI 不知道行业特殊性
- 不主动询问
- 完成后才发现不匹配

### 陷阱 3：技能退化

**长期影响**：
- 用户依赖 AI 做决策
- 自己不再思考"为什么"
- 失去判断能力

**实际案例**（业界报告）：
- 长期使用 Copilot 的开发者，独立编码能力下降
- 学生使用 ChatGPT，论文质量降低（不思考论点）

---

## 设计意图：协作而非替代

### BMAD 的引导哲学

**核心信念**：
- AI 是协作者，不是替代者
- 用户保持决策权
- AI 提供信息和建议，用户做选择

### 具体实现

**1. 主动询问**

在 `src/bmm-skills/2-planning/create-prd/SKILL.md` 中：

```markdown
## 引导式询问

不要假设，要询问：

✅ 好的引导：
"你的目标用户是个人消费者还是企业？这会影响我们的设计方向。"

❌ 不好的引导：
[假设是 B2C，直接生成 PRD]
```

**2. 提供选项**

```markdown
## 选项展示

不要单选，要给选项：

✅ 好的引导：
"基于你的需求，有三种架构方案：
[1] 单体 + PostgreSQL（简单，适合 MVP）
[2] 微服务 + 多数据库（复杂，适合规模化）
[3] Serverless + DynamoDB（成本低，但锁定 AWS）

你倾向哪个？为什么？"

❌ 不好的引导：
[直接选择微服务，不解释原因]
```

**3. 解释决策**

```markdown
## 决策透明

不要黑盒，要透明：

✅ 好的引导：
"我推荐使用 PostgreSQL 而非 MongoDB。
原因：
1. 你的数据有强关系（订单-用户-商品）
2. 团队熟悉 SQL
3. 事务支持重要

但如果你有不同考虑，请告诉我。"

❌ 不好的引导：
[选择 MongoDB，不解释]
```

## 源码实现：引导模式

### 模式 1：渐进式询问

在 `src/bmm-skills/1-analysis/bmad-brainstorming/SKILL.md` 中：

```markdown
## 渐进式问题序列

不要一次问 20 个问题，分阶段：

阶段 1：理解问题
- 你想解决什么？
- 现状是什么？
- 谁受影响？

阶段 2：探索选项
- 你考虑过哪些方案？
- 各方案的优缺点？

阶段 3：澄清需求
- 必要功能 vs 可选功能？
- 时间约束？
- 资源约束？

每阶段 3-5 个问题，让用户思考，不要信息过载。
```

### 模式 2：选项 + 推荐

```markdown
## 选项 + 推荐模式

提供 2-4 个选项：
- 列出每个选项的优缺点
- 标注"推荐"（基于上下文）
- 说明推荐理由
- 允许用户选择其他

示例：

"对于支付集成，有以下选项：

[1] Stripe（推荐 ⭐）
   优点：国际化、文档好、社区大
   缺点：手续费稍高
   理由：你的用户是国际化的

[2] PayPal
   优点：用户熟悉
   缺点：API 复杂

[3] 自建支付
   优点：完全控制
   缺点：合规风险、开发成本高

你的选择？"
```

### 模式 3：检查点确认

```markdown
## 关键决策检查点

在以下时刻必须确认：

1. PRD 完成时
   - "PRD 已完成，请审查。
     是否符合你的预期？"

2. 架构决策时
   - "我建议使用 X 架构。
     这会影响后续开发，是否同意？"

3. Epic 分解时
   - "我将项目分解为 3 个 Epic：
     [列表]
     是否合理？需要调整吗？"

4. Story 实施前
   - "Story X 即将开始实施。
     验收标准是 [列表]。
     是否补充？"
```

## 设计哲学：用户智慧的杠杆

### 反例：替用户思考

**ChatGPT 风格**：
```
用户："写一篇关于 AI 的文章。"
ChatGPT：[直接写 1000 字]
用户：[修改 30%]
```

**问题**：
- AI 替用户做了所有决策
- 用户失去思考机会
- 输出未必符合用户深层意图

### BMAD 的方式：放大用户思考

```
用户："写一篇关于 AI 的文章。"
Mary："让我帮你聚焦：
- 受众是谁？
- 想传达什么核心观点？
- 文章长度？
- 风格（学术 / 通俗）？"

用户：[思考并回答]
Mary：[基于用户想法，提供结构建议]
用户：[确认或调整]
Mary：[基于明确的方向，写文章]
```

**优势**：
- 用户保持思考
- 输出贴合意图
- 用户能力得到锻炼

## 验证与证据

### 证据 1：用户决策点的数量

**对照实验**：

| 模式 | 用户决策点 | AI 决策点 |
|------|-----------|----------|
| **完全自动化** | 1（开始） | 50+ |
| **半自动化** | 5-10 | 20-30 |
| **BMAD 引导式** | 20-40 | 5-10 |

**关键观察**：
- BMAD 让用户做大部分决策
- AI 只在执行细节上自主
- 大方向由用户掌控

### 证据 2：返工率

**实际数据**（基于社区反馈）：

| 模式 | 返工率 |
|------|--------|
| **完全自动化** | 50-70%（"重做"） |
| **半自动化** | 20-30% |
| **BMAD 引导式** | 5-15% |

**关键观察**：
- 引导式前期慢，但返工少
- 总体效率更高

### 证据 3：用户满意度

| 维度 | 自动化 | 引导式 |
|------|--------|--------|
| **快感（开始时）** | 高 | 低 |
| **信任度** | 低 | 高 |
| **可控感** | 低 | 高 |
| **学习收获** | 低 | 高 |
| **长期满意度** | 中 | 高 |

## 诚实陈述：引导式的代价

### 代价 1：开始时较慢

**问题**：
- 不能"一键生成"
- 需要回答多个问题
- 体感不"炫酷"

**实际数据**：
- 自动化：5 分钟出 demo
- 引导式：30-60 分钟出可用 PRD

**用户反馈**：
- "太慢了，我只想快速试试"
- "我没时间回答这些问题"

**缓解措施**：
- Level 0 跳过（快速场景）
- 提供"快速模式"
- 文档说明：前期投入换长期收益

### 代价 2：用户疲劳

**问题**：
- 大量决策点
- 决策疲劳
- 用户可能"随便选"

**实际影响**：
- 长流程末尾质量下降
- 用户可能放弃

**缓解措施**：
- 渐进式询问（3-5 个一组）
- 提供"推荐选项"（减少选择负担）
- 允许中断和恢复

### 代价 3：依赖用户配合

**问题**：
- 用户不回答 → 流程无法继续
- 用户回答模糊 → AI 困惑
- 用户回答自相矛盾 → 需要澄清

**实际场景**：
```
AI："你的目标用户是？"
User："所有人。"
AI："请更具体一些..."
User："就是所有需要这个的人。"
[僵局]
```

**缓解措施**：
- 提供示例答案
- 引导式追问
- 有"放弃此问题"的选项

## 案例研究：Mary 的引导艺术

### 场景：模糊的需求

**用户初始描述**：
> "我想做一个能让团队更高效的工具。"

### 直接生成的结果（反例）

**自动化 AI**：
```
[生成一个通用的项目管理工具]
- 任务管理
- 团队协作
- 文档共享
- 时间追踪
```

**问题**：
- 太通用
- 与现有工具雷同
- 不知道用户真正的痛点

### Mary 的引导（正例）

**Mary 的问题序列**：

```
Mary: "'更高效'是个好目标。让我帮你具体化：

  你说的团队，规模多大？
  现在用什么工具？哪些不满意？"

User: "5 人团队，用 Slack + Trello，
       但信息分散，找东西困难。"

Mary: "了解了。'信息分散'具体指：
  
  [1] 决策记录在 Slack 找不到了
  [2] 任务在 Trello，相关文档在别处
  [3] 知识没人整理，新人难上手
  [4] 其他
  
  最痛的是？"

User: "[1] 和 [2]。决策和任务关联性丢失。"

Mary: "明白了。所以你需要的是：
  
  '决策与任务关联的工具'
  
  而不是'另一个 Slack' 或 '另一个 Trello'。
  
  这个理解对吗？"

User: "对！就是这个！"

Mary: "好的，让我们围绕这个核心展开 PRD..."
```

### 结果对比

**自动化结果**：
- 通用工具
- 用户重做率：60%

**Mary 引导结果**：
- 精准定位（决策-任务关联）
- 用户重做率：10%
- 用户感叹："Mary 比我自己还懂我的需求"

## 设计原则提炼

从引导式协作中，可以提炼出一个核心原则：

> **AI 是放大器，不是替代品**

**具体体现**：

1. **询问而非假设**：减少错误前提
2. **选项而非单选**：保留用户选择权
3. **解释而非黑盒**：让决策可审视
4. **检查点而非一气呵成**：允许调整

**统一思想**：
- AI 应该让人类**更聪明**，而非更懒
- AI 应该让人类**更有掌控感**，而非更被动
- AI 应该让人类**学到东西**，而非外包思考

**项目质量**（6 个月后回顾）：

| 指标 | 自动化 | 引导式 |
|------|--------|--------|

| **返工次数** | 5-8 次 | 1-2 次 |

| **团队能力提升** | 否 | 是 |

| 阶段 | 自动化 | 引导式 |
|------|--------|--------|
| **初始生成** | 1 小时 | 5 小时 |
| **首轮修改** | 10 小时 | 2 小时 |
| **二轮修改** | 8 小时 | 1 小时 |
| **三轮修改** | 5 小时 | 0.5 小时 |
| **总计** | 24 小时 | 8.5 小时 |

**节省**：65% 时间
